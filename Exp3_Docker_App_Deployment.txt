==========================================================
EXPERIMENT 3: DOCKER BASED APP DEPLOYMENT
==========================================================

----------------------------------------------------------
1. AIM
----------------------------------------------------------
To install Docker on Ubuntu, build a Docker image for a web
application using a Dockerfile, and deploy (run) it as a
container.

----------------------------------------------------------
2. THEORY (learn this)
----------------------------------------------------------
DOCKER
  Open source platform that packs an application and everything
  it needs (code, libraries, runtime) into a small portable unit
  called a CONTAINER. It runs the same on any machine.

IMAGE
  A read-only template (blueprint) used to create containers.
  Image = recipe. Container = the cooked dish.

CONTAINER
  A running instance of an image. Light, fast, isolated.

DOCKERFILE
  A text file with instructions to build an image.

DOCKER HUB
  Online registry (store) of images. Example: nginx, python.

DOCKER ENGINE / DAEMON
  The background service (dockerd) that builds and runs
  containers.

CONTAINER vs VIRTUAL MACHINE
  VM        : has full guest OS, heavy (GBs), slow start, uses
              a hypervisor.
  Container : shares the host OS kernel, light (MBs), starts in
              seconds, uses Docker engine.

WHY DOCKER IN CLOUD
  Portability, fast deployment, scalability, "works on my
  machine" problem solved, microservices friendly.

KEY DOCKERFILE KEYWORDS
  FROM    = base image
  WORKDIR = working folder inside container
  COPY    = copy files from host to image
  RUN     = run a command while BUILDING image
  EXPOSE  = port the app uses
  CMD     = command to run when container STARTS

----------------------------------------------------------
3. DIAGRAM (draw this)
----------------------------------------------------------

   Dockerfile  --docker build-->  Image  --docker run-->  Container
   (recipe)                      (template)               (running app)
                                    |
                               Docker Hub (pull / push)

   Browser --> Host port 5000 --> Container port 5000 (app)

==========================================================
PART A: INSTALL DOCKER
==========================================================

STEP 1: Update system
    sudo apt update

STEP 2: Install Docker
    sudo apt install -y docker.io

STEP 3: Start and enable Docker service
    sudo systemctl start docker
    sudo systemctl enable docker
    sudo systemctl status docker
  Expected: "active (running)". Press q to exit.

STEP 4: Run docker without sudo (optional but handy)
    sudo usermod -aG docker $USER
    newgrp docker
  (If it still asks permission, logout and login again, or just
  use sudo before docker commands.)

STEP 5: Check version
    docker --version

STEP 6: Test installation
    docker run hello-world
  Expected: message "Hello from Docker! This message shows that
  your installation appears to be working correctly."

==========================================================
PART B: RUN A READY-MADE IMAGE (NGINX) - QUICK DEMO
==========================================================

STEP 1: Pull the image
    docker pull nginx

STEP 2: See images
    docker images

STEP 3: Run container
    docker run -d --name mynginx -p 8080:80 nginx
  -d = background, --name = give a name,
  -p 8080:80 = host port 8080 -> container port 80

STEP 4: Check running containers
    docker ps

STEP 5: Test
    curl http://localhost:8080
  (or open browser http://localhost:8080)
  Expected: "Welcome to nginx!" page.

STEP 6: Clean up this demo
    docker stop mynginx
    docker rm mynginx

==========================================================
PART C: DEPLOY YOUR OWN APP (MAIN EXPERIMENT)
==========================================================
We build a small Python Flask web app and put it in a container.

STEP 1: Create project folder
    mkdir ~/dockerapp
    cd ~/dockerapp

STEP 2: Create the app
    nano app.py
  Paste:
    from flask import Flask
    app = Flask(__name__)

    @app.route("/")
    def home():
        return "<h1>Hello from my Docker container!</h1>"

    @app.route("/about")
    def about():
        return "This app is deployed using Docker."

    if __name__ == "__main__":
        app.run(host="0.0.0.0", port=5000)

STEP 3: Create requirements file
    nano requirements.txt
  Paste:
    flask

STEP 4: Create the Dockerfile (file name must be exactly Dockerfile)
    nano Dockerfile
  Paste:
    FROM python:3.11-slim
    WORKDIR /app
    COPY requirements.txt .
    RUN pip install --no-cache-dir -r requirements.txt
    COPY . .
    EXPOSE 5000
    CMD ["python", "app.py"]

  Explain line by line (for viva):
    FROM python:3.11-slim  -> start from a small Python image
    WORKDIR /app           -> work inside /app folder
    COPY requirements.txt  -> copy dependency list
    RUN pip install ...    -> install Flask inside image
    COPY . .               -> copy our app code
    EXPOSE 5000            -> app uses port 5000
    CMD [...]              -> start the app

STEP 4B: Check files
    ls
  Expected: Dockerfile  app.py  requirements.txt

STEP 5: BUILD the image
    docker build -t myflaskapp:1.0 .
  -t = tag (name:version). The dot means "current folder".
  Expected: "Successfully built" / "naming to myflaskapp:1.0"

STEP 6: Check image
    docker images

STEP 7: RUN the container
    docker run -d --name flaskcontainer -p 5000:5000 myflaskapp:1.0

STEP 8: Verify it is running
    docker ps

STEP 9: TEST the app
    curl http://localhost:5000
    curl http://localhost:5000/about
  Or browser: http://localhost:5000
  Expected: "Hello from my Docker container!"

STEP 10: View logs
    docker logs flaskcontainer

STEP 11: Go inside the container (optional)
    docker exec -it flaskcontainer bash
    ls
    exit

STEP 12: Stop, start, remove
    docker stop flaskcontainer
    docker start flaskcontainer
    docker stop flaskcontainer
    docker rm flaskcontainer
    docker rmi myflaskapp:1.0     (removes image)

==========================================================
PART D (OPTIONAL BONUS): DOCKER COMPOSE
==========================================================
Compose runs many containers with one file.

    sudo apt install -y docker-compose-v2      (Ubuntu 24.04)
    (older Ubuntu: sudo apt install -y docker-compose)

    nano docker-compose.yml
  Paste:
    services:
      web:
        build: .
        ports:
          - "5000:5000"

    docker compose up -d        (older: docker-compose up -d)
    docker compose ps
    docker compose down

==========================================================
PART E (OPTIONAL BONUS): PUSH TO DOCKER HUB
==========================================================
    docker login
    docker tag myflaskapp:1.0 YOURUSERNAME/myflaskapp:1.0
    docker push YOURUSERNAME/myflaskapp:1.0
    (Then anyone can: docker pull YOURUSERNAME/myflaskapp:1.0)

----------------------------------------------------------
4. IMPORTANT DOCKER COMMANDS (cheat sheet)
----------------------------------------------------------
docker --version          version
docker pull IMAGE         download image
docker images             list images
docker build -t N:V .     build image from Dockerfile
docker run -d -p H:C IMG  run container in background
docker ps                 running containers
docker ps -a              all containers (even stopped)
docker logs NAME          see output
docker exec -it NAME bash enter container
docker stop NAME          stop container
docker start NAME         start again
docker rm NAME            delete container
docker rmi IMAGE          delete image
docker system prune       clean unused stuff

----------------------------------------------------------
5. COMMON ERRORS AND QUICK FIXES
----------------------------------------------------------
- "permission denied ... docker.sock"
    -> Use sudo docker ... or run:
       sudo usermod -aG docker $USER  then logout/login.
- "Cannot connect to the Docker daemon"
    -> sudo systemctl start docker
- "port is already allocated" / address already in use
    -> Use another host port: -p 5001:5000
       or stop old container: docker rm -f flaskcontainer
- "container name already in use"
    -> docker rm -f flaskcontainer
- Build fails: "Dockerfile not found"
    -> File name must be Dockerfile (capital D), and you must be
       in the same folder as it.
- pip install fails / cannot pull image
    -> No internet or proxy. Check: ping google.com
- Container exits immediately
    -> docker logs NAME  (shows the error in app.py)
- Page not opening
    -> App must use host="0.0.0.0", not 127.0.0.1.

7. LIKELY VIVA QUESTIONS WITH SHORT ANSWERS
----------------------------------------------------------
Q1. What is Docker?
A. A platform to package applications with their dependencies
   into containers so they run the same everywhere.

Q2. What is a container?
A. A lightweight, isolated running instance of an image.

Q3. What is an image?
A. A read-only template with app code, libraries and settings
   used to create containers.

Q4. Difference between image and container?
A. Image = blueprint (static). Container = running copy of the
   image.

Q5. Difference between container and VM?
A. Container shares host OS kernel, light and fast. VM has its
   own full OS on a hypervisor, heavy and slower.

Q6. What is a Dockerfile?
A. Text file with step by step instructions to build an image.

Q7. Difference between RUN and CMD?
A. RUN executes during image build. CMD runs when the container
   starts.

Q8. Difference between COPY and ADD?
A. COPY just copies files. ADD can also extract tar files and
   download from a URL. Prefer COPY.

Q9. What does -p 5000:5000 mean?
A. Port mapping: host port : container port.

Q10. What does -d mean?
A. Detached mode, container runs in the background.

Q11. What is Docker Hub?
A. Public registry to store and share images.

Q12. What is Docker daemon?
A. Background service (dockerd) that builds, runs and manages
   containers.

Q13. What is EXPOSE?
A. Documents which port the app listens on. It does not publish
   the port by itself, -p does.

Q14. How do you see running containers?
A. docker ps  (all: docker ps -a)

Q15. How to persist data in Docker?
A. Use volumes: docker run -v myvol:/data IMAGE

Q16. What is Docker Compose?
A. Tool to define and run multi-container apps using a
   docker-compose.yml file.

Q17. What is a Docker network?
A. Virtual network that lets containers talk to each other.
   Default is bridge.

Q18. Why is Docker popular in cloud?
A. Fast, portable, scalable, efficient, good for microservices
   and CI/CD.

Q19. What is the base image?
A. The starting image in FROM, like python or ubuntu.

Q20. What is orchestration? Name tools.
A. Managing many containers automatically (scaling, healing).
   Tools: Kubernetes, Docker Swarm.

----------------------------------------------------------
8. MEMORY TRICKS
----------------------------------------------------------
- Docker flow: WRITE Dockerfile -> BUILD image -> RUN container
- Image = Recipe, Container = Dish
- Dockerfile keywords: "FWCRECe" = FROM, WORKDIR, COPY, RUN,
  EXPOSE, CMD
- Port mapping -p HOST:CONTAINER  ("Host first")
- 4 commands you must remember: build, run, ps, logs
